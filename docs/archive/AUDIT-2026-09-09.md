## B1 — CRITICAL: copy ids are positional, so a cache skew makes copies show *other copies'* questions

**Severity: critical (silent wrong data, self-heals within 12 h so it is nearly unreportable).**

### What is wrong

`build.js` assigns `i: i++` in `groups` iteration order (`build.js` ~line 208 and ~236). That order
is the row order of `questions.csv` → `submissions.csv` → `ocr-questions.csv`, then link-copies.
**Insert one row anywhere and every id after it shifts.**

Reproduced — appending a single submission row to a fresh clone:

```
before: 8075 copies    after: 8076 copies
ids still pointing at the SAME url:  1063
ids now pointing at a DIFFERENT url: 7012   ← 87 % of the corpus
```

The app then merges three separately-cached files **by that id**:

- `data/index.json` is in `sw.js`'s `SHELL` → **stale-while-revalidate** → after a deploy the first
  load gets **yesterday's** file.
- `data/copies.json` and `data/questions.json` are `DATA_HEAVY` → **cache-first with a 12 h TTL**,
  and each has its **own** TTL clock because each is fetched at a different moment (copies.json on
  idle, questions.json on search intent).

So the three files routinely come from different builds. `loadFull()` does
`known[c.i].q = c.q || []`, and `questions.json`'s `a: [[copyId, page]]` resolves through
`COPYBYID`. Simulated against two real builds one submission apart:

```
copies that would display ANOTHER copy's questions: 7012 of 8075
  id 1262  card shows: "Aayushi Bansal" — GS Paper 2 copy
           question shown: "In many ways, the Spanish civil war was the opening act of WwI…"
  id 1263  card shows: "Aayushi Bansal" — Ethics Paper copy
           question shown: "Discuss the role of the 'Fourth Estate' in upholding democratic values…"
```

Every "Open PDF · p.N" link on those cards points at the wrong page of the wrong PDF. The
question-first view and Practice list the wrong toppers for the right question. The nightly
`ocr-gemini` pass commits `ocr-questions.csv` most nights, so ids churn most nights.

### Fix — stamp a build id and make the app refuse to merge across builds

**1. `build.js`** — compute one build id and write it into all three files.

Inside `build()`, right after `const generated = new Date().toISOString().slice(0, 10);`, add:

```js
// Copy ids are positional, so they change whenever a row is inserted anywhere upstream.
// Every file that carries or references them is stamped with the same build id; the app
// refuses to merge two files that disagree (see assets/app.js loadFull/loadQuestionIndex).
const buildId = crypto.createHash('sha1')
  .update(copies.map(c => c.i + '|' + c.u).join('\n')).digest('hex').slice(0, 12);
```

Then add `build: buildId` to each of the three payloads:

- `data/copies.json` — `JSON.stringify({ generated, build: buildId, attribution: ATTRIBUTION, format: 2, stats, copies: wireCopies })`
- `data/index.json` — `JSON.stringify({ generated, build: buildId, attribution: ATTRIBUTION, stats, copies: lite })`
- `data/questions.json` — written by `writeQuestions()`, which runs **before** `buildId` exists.
  Do **not** move `writeQuestions()`. Instead extend the existing post-pass that already folds
  `variants` in (the `if (variants.length) { … }` block just after `copies.json` is written) into an
  unconditional one that also sets `build`:

```js
// questions.json is written before the ids exist; fold in the variant table and the build id now.
{
  const qp = path.join(DATA, 'questions.json');
  const payload = JSON.parse(fs.readFileSync(qp, 'utf8'));
  payload.build = buildId;
  if (variants.length) payload.variants = variants;
  fs.writeFileSync(qp, JSON.stringify(payload));
}
```

**2. `assets/app.js`** — add a helper next to `loadFull` that re-fetches past the caches on mismatch.
A plain `{cache:'reload'}` does **not** work: `sw.js` matches `DATA_HEAVY` by pathname and returns
the cached body regardless. Use a query string, and teach `sw.js` to pass those straight through
(step 3).

```js
  // The three data files are cached independently (SHELL = stale-while-revalidate,
  // copies/questions = cache-first with a 12 h TTL), and copy ids are positional — so a
  // mismatched pair would attach one copy's questions to another. Fetch, and if the build
  // id disagrees with what we already hold, go round the caches once and take the newest.
  function fetchAtBuild(url, want) {
    return fetch(url).then(function (r) { return r.json(); }).then(function (d) {
      if (!want || !d.build || d.build === want) return d;
      return fetch(url + '?b=' + encodeURIComponent(d.build || 'x') + '.' + Date.now())
        .then(function (r) { return r.json(); });
    });
  }
```

In `loadFull()`, replace `fetch('data/copies.json').then(function (r) { return r.json(); })` with
`fetchAtBuild('data/copies.json', DB && DB.build)`, and inside the `.then(function (d) { … })`
add a full rebuild before the existing merge loop:

```js
      QBYID = {};
      DB.copies = DB.copies.filter(function (c) { return !c.stub; });
      // Boot index and full file came from different builds — ids no longer line up, so the
      // id-keyed merge below would splice one copy's questions onto another. copies.json is a
      // strict superset of index.json, so drop the lite rows and rebuild wholly from it.
      if (d.build && DB.build && d.build !== DB.build) {
        DB.copies = [];
        DB.build = d.build;
        DB.generated = d.generated || DB.generated;
        if (d.stats) DB.stats = d.stats;
      }
      var known = {};
      DB.copies.forEach(function (c) { known[c.i] = c; });
      /* …existing d.copies.forEach loop, unchanged… */
```

In `loadQuestionIndex()`, gate on `copies.json`'s build (its `a[[copyId, page]]` refs are only
meaningful against that build) and re-fetch on mismatch:

```js
    qiPromise = ensureFullPromise().then(function () {
      return Promise.all([
        fetchAtBuild('data/questions.json', DB && DB.build),
        fetch('data/syllabus.json').then(function (r) { return r.json(); }).catch(function () { return null; })
      ]);
    }).then(function (res) { /* …unchanged… */ });
```

where `ensureFullPromise()` is `function () { ensureFull(); return fullPromise || Promise.resolve(); }`.
(Text search itself does not need copies.json, but the answer lists do, and `loadFull` is already
fired on the same intent — the extra wait costs nothing in practice.)

**3. `sw.js`** — never serve a cache-busted heavy request from the cache, and bump `VERSION`:

```js
  if (DATA_HEAVY.test(url.pathname)) {
    if (url.search) return;          // explicit cache-buster from app.js — straight to the network
    e.respondWith( /* …unchanged… */ );
    return;
  }
```

Bump `VERSION` to `tc-v16`.

## B4 — HIGH: an approved submission can inject a `javascript:` URL into the live site

**Severity: high (stored XSS on the site's own origin; needs one moderator approval).**

`.github/scripts/apply-submission.mjs` never validates the URL scheme —
`grep -c 'https\?://' .github/scripts/apply-submission.mjs` → `0`. Reproduced end to end:

```
$ node .github/scripts/apply-submission.mjs /tmp/js-url.md
Added optional-subject copy: Zzz Evil — Law · no question text
javascript:alert(document.domain
```

and after `node build.js`:

```
topper/zzz-evil/index.html:55   <a href="javascript:alert(document.domain" …>Open copy</a>
optional/law/index.html:94      <a href="javascript:alert(document.domain" …>Open copy</a>
```

`esc()` escapes the *value* but a `javascript:` scheme in an `href` is still live. The link text is
"Open copy", so nothing looks wrong in review. A moderator is checking "is this a genuine topper
copy", not "is this URL scheme safe". Payload gets the site's origin: `localStorage` (theme,
practice state), the service-worker registration, and full control of the page.

### Fix — validate at all three layers

**1. `.github/scripts/apply-submission.mjs`** — reject at the gate. After the `const url = pick(…)`
line add:

```js
// Only ever link out to a real web URL. A javascript:/data: scheme here would end up in an
// href on /topper/<slug>/ and /optional/<subject>/ and run on our own origin.
function assertHttpUrl(u, what) {
  let p;
  try { p = new URL(u); } catch (e) { console.error(`${what} is not a valid URL: ${u}`); process.exit(1); }
  if (p.protocol !== 'http:' && p.protocol !== 'https:') {
    console.error(`${what} must be an http(s) link — got "${p.protocol}".`); process.exit(1);
  }
  return p.toString();
}
```

and call it wherever `url` is used: in the optional branch immediately after
`if (!url) { … process.exit(1); }` → `assertHttpUrl(url, 'Copy link');`, and in the GS/Essay branch
before writing rows, for both the form `url` **and** every `url` column of the CSV block
(column index 6 of each data row) — a submitter controls that CSV too.

**2. `build.js`** — defence in depth, so a hand-edited or historical bad row cannot ship. Add next
to `esc`:

```js
// Every "Open PDF/copy" href points at a third-party host. Anything that is not http(s)
// must never reach an href — see AUDIT B4.
const safeHref = u => (/^https?:\/\//i.test(String(u || '')) ? esc(u) : '#');
```

Replace `esc(c.u)` / `esc(o.url)` / `esc(pdf)` inside every generated `href="…"` in
`writeTopperPages`, `writeToppersPage`, `writeQuestionPages` and `writeHubPages` with `safeHref(…)`.

**3. `assets/app.js`** — same at render time. Add near `esc`:

```js
  var safeHref = function (u) { return /^https?:\/\//i.test(String(u || '')) ? u : '#'; };
```

and wrap every `href:` that comes from data — in `answerRows`, `optAnswerRows`, `copyCard`
(both the link-only `la` and `renderQ`'s `a`), `optCard`'s `pdfLink`, and `topperTags`'
Telegram link.

## B6 — MEDIUM: a `|` in any submitted field breaks the submission

The Submit form builds a markdown table row per field (`assets/app.js`, `wireSubmit`'s submit
handler). A topper name of `Test | Topper` produces:

```
| Topper | Test | Topper |
```

`apply-submission.mjs`'s row regex is `/^\|\s*([^|]+?)\s*\|\s*([^|]*?)\s*\|\s*$/gm` — three inner
pipes never match, so the field vanishes and the moderator gets:

```
$ node .github/scripts/apply-submission.mjs /tmp/pipe.md
No topper name in the issue body.
exit=1
```

The workflow then strips the `approved` label and comments the error, so the submission looks
broken for no visible reason. Real names hit this: `Ramesh | ForumIAS`, `GS2 | Essay`, any
`Source / coaching` field a submitter pastes with a separator.

### Fix — both ends

**`assets/app.js`**, in the submit handler, add a cell escaper and use it for every interpolated
value in the `L` array:

```js
      // markdown table cells: a raw | would split the row and break the parser in
      // .github/scripts/apply-submission.mjs
      var cell = function (s) { return String(s == null ? '' : s).replace(/\|/g, '\\|').replace(/\r?\n/g, ' '); };
```

then `'| Topper | ' + cell(g('topper')) + ' |'`, and likewise for AIR, Year, Paper / subject,
Copy link, Source / coaching, Marks, Subject-wise marks and Submitted by.

**`.github/scripts/apply-submission.mjs`** — accept escaped pipes and be tolerant of extra ones.
Replace the table-row loop with:

```js
for (const line of body.split('\n')) {
  const m = line.match(/^\s*\|(.+)\|\s*$/);
  if (!m) continue;
  // split on unescaped pipes only, then unescape
  const cells = m[1].split(/(?<!\\)\|/).map(s => s.trim().replace(/\\\|/g, '|'));
  if (cells.length < 2) continue;
  const k = cells[0].toLowerCase();
  const v = cells.slice(1).join(' | ').trim();   // tolerate a stray unescaped pipe
  if (k === 'field' || /^-+$/.test(k)) continue;
  fields[k] = v;
}
```

(Node 20 supports lookbehind; CI is on Node 20.)

### Verify



This takes everything after the **last** comma as the URL. Once B7 quotes the URL — or for any
already-unquoted comma URL — this returns a fragment, not a URL. Consequences in the same function:

- `freshBases.has(b)` misses → committed rows for a copy that *was* re-read are kept **and** the
  fresh rows are added → duplicate questions accumulate in `ocr-questions.csv` every night.
- `opByBase.has(b)` misses → a stale optional-subject row is not dropped → the copy shows twice
  (once in Optionals, once as a bare GS copy).

### Fix

Parse the row properly instead of string-slicing. `ocr-pipeline.mjs` already imports nothing for
CSV, so add a tiny last-field reader next to `rowBase`:

```js
// Read the 7th (url) field of a CSV row properly — a quoted question or a url containing a
// comma makes lastIndexOf(',') point at the wrong place. See AUDIT B8.
const lastField = line => {
  const out = []; let cur = '', q = false;
  for (let i = 0; i < line.length; i++) {
    const c = line[i];
    if (q) { if (c === '"') { if (line[i + 1] === '"') { cur += '"'; i++; } else q = false; } else cur += c; }
    else if (c === '"') q = true;
    else if (c === ',') { out.push(cur); cur = ''; }
    else cur += c;
  }
  out.push(cur);
  return out[out.length - 1];
};
const rowBase = line => norm(lastField(line));
```

```js
if (dlg.showModal && !dlg.open) dlg.showModal(); else dlg.setAttribute('open', '');
```

The `else` now also fires when `showModal` exists and the dialog is already open, setting the
`open` attribute on a modal dialog. Harmless today but the branch no longer means what it reads as.
Prefer:

```js
if (dlg.open) { /* already open */ }
else if (dlg.showModal) dlg.showModal();
else dlg.setAttribute('open', '');
```

**c. Dead code.** `assets/app.js`'s search-tracking debounce reads
`results: (res && res.pending) ? -1 : res.length` — `filteredCopies()` returns a plain array and
never has `.pending`. Drop the ternary.

**d. `setView`'s scroll behaviour.**
`behavior: 'instant' in document.documentElement.style ? 'instant' : 'auto'` tests for a **CSS
property** named `instant`, which never exists, so it is always `'auto'`. Just pass `'instant'` —
it is a valid `ScrollBehavior` and browsers that do not know it fall back to `auto`.

**e. Prototype-key hazard.** `topperOptions()`, `sourceOptions()`, `optCounts()` and
`assets/extract.js`'s `seen` use bare `{}` keyed by data-derived strings. A value of `constructor`
would produce garbage counts. Use `Object.create(null)` (or a `Map`) in those four places. Very low
likelihood; two-line fix.

**f. Optionals subject view has no pagination.** Picking Sociology renders all 342 cards, every one
`open`. Measured at 25 ms / 4,811 nodes on desktop — fine today, but it scales linearly and the
Browse view already has the `state.shown` pattern to copy if it becomes a problem.
